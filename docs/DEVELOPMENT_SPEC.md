# KTB RTD 의사결정 보조 도구 개발명세서

버전: 2026-10-29 외국인 가격대 지도, 시간가중 호가 누적 관측, 수급·가격 자연어 요약 카드, 그래프 증분 읽기, 현물 5년 곡률 기준과 3Y/10Y 교차 베이시스, 실행시점 표준채권 DV01, 당일 복원 반영. 기존 점검 결과와 이후 구현 상태를 기술하며 미래 계획을 완료 기능으로 포함하지 않는다.

## 1. 목적과 시스템 경계

CheckExpert RTD가 갱신하는 기존 Excel을 읽어 3년·10년 국채선물 호가를 수집하고, 장중 상대가격/호가잔량/수동 위험값을 사람이 해석할 수 있게 표시한다. 주문 송신·취소·체결조회·계좌 연결·원본 workbook 저장 기능은 없다. `research entry`는 재생기의 가상 상태이며 실제 주문이 아니다.

입력 신뢰 경계: RTD/Excel → 수집기, CSV → 신호 엔진, settings.json → 계산 설정. 각각 숫자/형식 검증은 수행하나 공급자 정합성, 거래소 시각, 입력 DV01의 경제적 정확성을 인증하지 않는다.

### 2.1 이번 변경에서 추가·확장한 기술 구성

새로운 외부 패키지를 설치하는 대신 기존 Python 표준 라이브러리와 Tkinter의 사용 범위를 확장했다. `requirements.txt`는 이번 변경에서 바꾸지 않는다. 실행 환경은 CPython 3.12.13 32비트, xlwings 0.33.22, pywin32 312를 실제 설치 메타데이터로 다시 확인했다.

| 기술/자료구조 | 사용 모듈 | 추가한 역할 및 선택 이유 |
|---|---|---|
| `dataclasses.dataclass(frozen=True)` | `flow_brief.py`, `foreign_profile.py` | `FlowBrief`와 `PriceBand`에 표시용 결과를 담는다. 계산과 위젯 조작을 분리하고 결과의 필드 변경을 막는다. |
| `dataclass(slots=True)` + `collections.deque` | `book_pressure.py` | 시간 구간을 작은 `_Segment` 객체로 저장하고 창 밖 구간을 앞에서 제거한다. 매번 과거 행 전체를 다시 계산하지 않는다. |
| 구간 적분 합계와 경계 절단 | `BookPressureTracker`, `_Window`, `_Totals` | 관측 횟수가 아닌 경과시간으로 OBI·가중 OBI·호가간격과 우위시간을 집계한다. 창 경계에 걸친 구간은 해당 초수만 반영한다. |
| Tkinter `Canvas` | `ForeignPriceProfile` | 가격대별 수평 막대·현재가 선·툴팁을 직접 그린다. 브라우저, Matplotlib, Pandas를 실행 경로에 추가하지 않는다. |
| Tkinter `Toplevel`, 공유 `StringVar` | `dashboard_widgets.open_profile_window` | 큰 가격대 지도 창과 탭이 같은 매수/매도·순매수 보기 상태를 공유한다. 새로운 시세 연결을 만들지 않는다. |
| `after`, `after_cancel`, `time.monotonic` | `ForeignPriceProfile` | 데이터 재그리기 간격을 제한하고 크기 변경을 지연 처리한다. 위젯별 예약 하나만 유지하며 종료 때 취소한다. |
| 버전 기반 캐시, 불변 가격 구간 tuple | `ForeignFlowTracker.price_profile` | 수량이 변한 경우에만 가격별 스냅샷을 다시 정렬·구성한다. 탭과 큰 창은 같은 스냅샷을 사용한다. |
| `ThreadPoolExecutor(max_workers=1)` | 기존 `spread_chart.py` 개선분 | 별도 스프레드 그래프의 CSV 읽기·집계를 UI 밖에서 수행한다. 이번 요약 카드·호가 추적·외국인 지도 자체는 대시보드 메인 루프를 사용한다. |
| `unittest`, `unittest.mock` | 새 시험 3개 파일 및 `test_safety.py` | 순수 계산 검산과 대시보드 연결 경로를 검증한다. 실시간 Excel을 테스트에서 조작하지 않는다. |

### 3.2 수집·복원·표시를 연결한 순서

1. 수집기는 기존 RTD 읽기 정책으로 행을 저장한다. 추가된 세 화면 때문에 Excel을 더 읽거나 CSV 열을 추가하지 않는다.
2. 시작 시 `IncrementalCsvTail`이 당일 파일에 연결하고 `ForeignHistoryReplay`가 연결 시점까지의 고정된 범위를 배치로 읽는다. 현재 구현의 기본 배치는 500행이다. 날짜가 다른 행·미래 시각·불량 행은 복원 관측에 사용하지 않는다.
3. 과거 행은 외국인 추적기와 새로운 호가 추적기를 예열한다. `ForeignFlowTracker`는 매수/매도 가격 구간과 최근 수급을, `BookPressureTracker`는 시간 구간 적분을 복원한다. 과거 알림·합의신호를 새로 발생시키지 않는다.
4. 복원 후 새 행은 기존 `SignalEngine`, 이벤트 호가 점수, 현물/상대가치 추적과 함께 두 관측 추적기에 한 번씩 전달한다. 라이브 처리 루프의 250행/약 20ms 배치 제한과 바쁜 동안의 25ms 재예약을 유지한다.
5. `_render_overview`는 같은 만기의 수급 `summary()`를 카드와 기존 상세 문구에 공유한다. 호가 누적 표시도 기존 `summary()` 합계에서 계산하고 파일을 다시 검색하지 않는다.
6. 외국인 탭이 선택되거나 큰 창이 열렸을 때 가격 구간 스냅샷을 요청한다. Tk Canvas는 최신 결과를 최대 2초에 한 번 그리며, 모드·최신성 변경과 크기 변경에는 별도의 짧은 갱신 규칙을 적용한다.
7. 대시보드 재실행 때 메모리 객체는 새로 만들어지고 오늘 CSV에서 같은 규칙으로 재구성된다. 별도의 새 체크포인트 파일이나 계좌 원장은 만들지 않는다. 수집기가 꺼져 로그가 없던 시간의 가격·체결을 복원하지 않는다.

## 4. 입력 데이터 계약

Excel 파일명 기본값은 `국채선물 호가창.xlsx`, 시트는 `Sheet1`이다. 열 배치는 고정되어 있으며 변경되면 수집 코드도 수정해야 한다. 열린 workbook을 파일명으로 찾으므로 동일 파일명의 여러 workbook이 열려 있지 않도록 운영해야 한다.

| 데이터 | 3Y (`KBFA020`) | 10Y (`KXFA020`) |
|---|---|---|
| 매도 가격, 잔량 | D2:D6, C2:C6 | L2:L6, K2:K6 |
| 매수 가격, 잔량 | D7:D11, E7:E11 | L7:L11, M7:M11 |
| 마지막 체결가 | G2 | O2 |

한 번의 `C2:O11` 값 읽기로 두 종목을 가져온다. COM 왕복을 줄이지만 RTD 계산 자체의 원자적 동시성을 보장하지 않는다. `timestamp_utc`는 **읽기 직후 PC UTC 시각**이며 거래소 체결시각이 아니다. 체결가 셀 값 변화가 개별 체결 이벤트를 완전하게 나타내지도 않는다.

수집 검증: 기본 호가 가격/잔량은 유한한 양수, 각 측 5개, 가격 순서 정상, best ask > best bid. Excel의 ask는 5호가→1호가이므로 반전한다. 기본 호가의 빈 값·문자열 오류·bool·NaN/Infinity·0/음수·역전·잠김은 해당 스냅샷 저장을 보류한다. 반면 마지막 체결가나 추가 RTD 현물·선물수익률이 0·공란·비정상이면 해당 선택 지표만 공란(`N/A`)으로 저장하고 정상 호가 수집은 계속한다. 외국인 누적 매수·매도 수량의 0은 유효하다. 잔량 0이나 locked book이 정상적으로 존재할 수도 있으나 현재 연구기는 보수적으로 분석 불가로 취급한다. 실제 시장 단계 구분은 없다.

기본 호가 로그 열은 총 61개: 시각 1개 + 각 종목 30개. 종목별 체결가 1개, best_bid/ask·mid·spread·bid/ask_depth·OBI·WOBI·microprice 9개, 5단계 가격·잔량 20개다. 현재의 추가 RTD 활성 로그에는 선택 지표와 파생 금리차 열이 더 붙으며, 값이 공란이어도 열 구성은 유지한다. 가격 단위는 선물 호가 포인트, 잔량은 공급자의 계약 수 단위다. DV01은 원/bp/계약이며 수익률 퍼센트가 아니다.

`추가RTD`의 현재 연결은 B1/B2 현물 3Y/10Y 체결수익률(%), B3/B4 3Y 외국인 누적 매수/매도, B6 3Y 선물수익률(%), B7/B8 10Y 외국인 누적 매수/매도, B10 10Y 선물수익률(%)이다. B5/B9 선물가격도 존재하지만 본 수집기의 기존 체결가 셀 G2/O2와 같은 15001 필드이므로 중복 저장하지 않는다. 선택 필드 `cash_5y_yield_pct`, `cash_5y_time`, `cash_5y_bond`를 추가할 수 있으며 셀 주소는 고정하지 않는다. 새 선택 열은 기존 당일 CSV 헤더와 호환되지 않으므로 장 시작 전·다음 거래일에 연결하거나 기존 당일 로그를 보관 이동한 뒤 시작해야 한다. 추가 연결 활성화 시 로그 `snapshots_enhanced`를 사용하며 기존 61열 로그를 변경하지 않는다.

공통 엔진은 timezone 포함 시각, 두 종목의 유한 양수 mid/best bid/ask/spread, 양의 스프레드, bid/ask와 mid/spread 일치성을 검증한다. 나머지 호가 필드 전체를 재계산하지는 않는다. UI는 추가 표시 지표의 유한성도 검사한다.

## 5. 계산식

### 5.1 호가 지표

```text
mid = (best_bid + best_ask) / 2
spread = best_ask − best_bid
bid_depth = Σ bid_qty[1..5], ask_depth = Σ ask_qty[1..5]
OBI = (bid_depth − ask_depth) / (bid_depth + ask_depth)
weights = [1.0, 0.7, 0.5, 0.3, 0.2]  # 가까운 호가부터
WOBI = (Σ weights×bid_qty − Σ weights×ask_qty) / (Σ weights×bid_qty + Σ weights×ask_qty)
microprice = (best_ask×bid_qty1 + best_bid×ask_qty1) / (bid_qty1 + ask_qty1)
```

microprice는 잔량가중 중심값이지 체결가격 예측모델이 아니다. 현재 화면의 pressure 점수는 `0.3×OBI + 0.5×WOBI + 0.2×clip((microprice−mid)/(spread/2),−1,1)`을 가중치 합으로 나눈 후 EMA를 적용한다. 해당 종목의 입력 지표가 바뀐 경우에만 EMA를 갱신한다. 동일 heartbeat 수에 따라 점수가 변하지 않지만 실제 시장 이벤트 속도에 따른 시간 길이는 고정되지 않는다. 상대 점수는 10Y−3Y이며 ±0.25는 미검증 연구 임계값이다.

### 5.1A 호가 누적 관측 (2026-10-29)

기존 `OrderFlowAnalyzer`의 이벤트 EMA는 실제 시간 길이가 고정되지 않는다. 별도 `BookPressureTracker`를 3년·10년 각각 두어, 기존 점수와 독립적인 시간가중 통계를 `호가 · 비용` 탭 맨 위에 표시한다.

```text
유효 관측쌍 (t_i, x_i), (t_{i+1}, x_{i+1})에서:
Δt_i = t_{i+1} − t_i
유효 적분 = x_i × Δt_i
시간가중 평균 = Σ(x_i × Δt_i) / ΣΔt_i
매수우위 비율 = Σ(1[OBI_i ≥ +0.10] × Δt_i) / ΣΔt_i
매도우위 비율 = Σ(1[OBI_i ≤ −0.10] × Δt_i) / ΣΔt_i
중립 비율 = 1 − 매수우위 비율 − 매도우위 비율
최근 창 관측률 = 창 내 유효 Δt 합계 / 창 길이(300/900/3600초)
당일 관측률 = 당일 유효 Δt 합계 / (마지막 관측시각 − 첫 유효 관측시각)
```

- 평균 대상은 5단계 OBI, 근접호가 가중 OBI, 최우선 호가간격(pt)이다. ±0.10은 설명용 표시 구분선으로 수익률 예측·실행 임계값이 아니다. 전체 창을 채운 경우에만 5분 평균 방향을 표제로 표시하고, 각 기간에는 전체/부분·관측률과 우위시간 비율을 나란히 표시한다. 비율의 분모는 창 전체가 아닌 유효 관측시간이다. 당일은 오늘 로그의 기록 시작 이후 기준이며 장 시작 이후 전수 자료를 뜻하지 않는다.
- `x_i`는 다음 유효 관측까지 유지됐다는 샘플링 가정이다. 동일 heartbeat가 추가돼도 시간을 중복 계산하지 않는다. 현재 벽시계까지 직전 호가를 연장하지 않으며, 마지막 표본의 값은 다음 표본이 도착한 뒤 그 사이 시간에만 반영한다. 최신 관측이 멈추면 마지막 집계시각과 역사적 관측값으로 표시한다. RTD 원천 호가시각이 없어 공급값 자체 동결은 별도로 식별하지 못한다.
- `data.max_gap_seconds` 초과 공백, 유효하지 않은 지표, 역순/중복 시각에서 연속성을 끊고 중간 시간을 배정하지 않는다. 유효성은 OBI·가중 OBI의 유한값/[-1,1], 양의 호가간격, 음수가 아닌 양쪽 잔량과 양의 총잔량이다. 기존 대시보드의 호가 검증도 선행한다. 날짜(KST)·세션·연결된 계약월 변경은 해당 계약의 통계를 초기화한다. 일시 불량 입력 후에도 같은 날 누적된 호가 관측은 보존한다.
- 각 창은 `_Segment` deque와 증가/감소 적분 합계를 유지한다. 창 밖 구간은 빼고 경계에 걸친 구간은 정확한 초수만 절단한다. 동일 상태의 연속 구간은 합쳐 heartbeat 개수에 따른 메모리 증가를 줄인다. 60분보다 오래된 원시 구간은 보유하지 않으며 당일은 합계만 보관한다. 1초마다 상태가 바뀌는 경우 만기별 각 창에 최대 약 300/900/3600개 구간이 남는다.
- `Dashboard.refresh`에서 새 유효 행을 한 번씩 반영하며, 기존 당일 이력 복원 경로에도 같은 추적기를 연결한다. 누적 호가 관측 복원은 과거 신호·알림을 재생하지 않는다. 별도 CSV 검색·Excel COM 호출·파일·타이머·외부 패키지는 추가하지 않는다. 기존 이벤트 압력 점수와 신호·알림 계산은 이 통계를 입력으로 사용하지 않는다.
- 검증: 시간 간격이 다른 표본의 해석적 가중평균, heartbeat 간격 불변성, 창 경계 부분 절단, 공백·불량 입력·역순 시각, 날짜·세션·계약 변경, 당일 복원 및 지연 표시를 포함한 전체 96개 시험 통과. 모의 6.5시간(23,401행, 1초마다 양쪽 호가 변경)에서 두 만기 합산 처리시간은 약 1.45초, 행당 약 0.062ms였다. Excel·파일 I/O·UI 전체 부하 측정값은 아니다.

### 5.2 RV와 시간 기준

```text
beta = DV01_10Y / DV01_3Y  # 수동 DV01 또는 실행시점 자동 표준채권 DV01
       또는 rv.beta (수익률 미연결 시 기본 2.88, 연구용)
RV_t = mid10_t − beta×mid3_t
Z_fast = (현재 RV − 최근 이벤트 RV 평균) / 표본 표준편차(ddof=1)
Z_core = (현재 RV − 최근 N개 완료 분 RV 평균) / 표본 표준편차(ddof=1)
```

빠른 창은 최초 관측 이후 두 mid 중 하나가 달라질 때만 추가하며, deque는 최대 120개다. 현재 관측을 빠른 창의 평균/표준편차에 포함한다. 완료 분 기준은 해당 분에 마지막으로 관측한 RV를 다음 분 진입 시 확정한다. 현재 진행 중인 분은 참조 평균에 포함하지 않는다. 누락된 분은 이전 값으로 채우지 않는다. 최초 수집 분은 부분 분일 수 있으므로 60개 분 종가가 반드시 60분 연속 관측시간을 뜻하지는 않는다.

공통 엔진의 기본 공백 처리는 두 창과 합의 상태 초기화다. 현재 대시보드는 라이브·당일 복원 경로 모두 `preserve_history_on_gap=True`를 전달하므로 같은 날 `max_gap_seconds` 초과 공백에는 기존 관측창을 보존하고, 공백을 가로지르는 이벤트 변화와 1분 변화는 만들지 않으며 합의 상태를 초기화한다. KST 달력 날짜 변경·역순/동일 시각·불량 행은 별도 초기화 조건이다. 날짜 변경은 거래소 세션 달력 구현이 아니다. 특히 KRX 안내에는 야간 세션이 있으므로 자정 초기화를 야간 거래일 처리로 오해해서는 안 된다. [KRX 3년 상품명세](https://global.krx.co.kr/contents/GLB/02/0201/0201040501/GLB0201040501.jsp)

두 창의 표본 수를 충족하고 표준편차가 각각 1e-12보다 커야 ready다. 연구 상태는 `−1, 0, +1`이며 실제 보유 포지션과 무관하다.

1. state=+1이고 두 Z가 exit_z보다 크면 유지. −1은 두 Z가 −exit_z보다 작으면 유지.
2. 두 Z가 entry_z 이상이면 +1 후보, 두 Z가 −entry_z 이하면 −1 후보, 아니면 0 후보.
3. 후보가 바뀌면 확인 시간을 새로 시작. 같은 후보가 관측시각 기준 3초 지속되면 상태 변경.
4. heartbeat도 확인시간 판단에 사용한다. 관측 사이에 조건이 계속 성립했다는 것은 샘플링 가정이지 거래소 틱 단위 증명이 아니다.
5. 품질·워밍업·분산 조건 미충족 시 state=0. `entry_allowed`는 비용 및 설정 가상 위험한도 검사 결과이며 주문 승인이 아니다.

### 5.3 현물곡률 및 교차 베이시스

```text
cash_butterfly_bp = {Y5 − (5/7×Y3 + 2/7×Y10)} × 100
basis_3y_bp = (FYield3 − Y3) × 100
basis_10y_bp = (FYield10 − Y10) × 100
cross_basis_bp = basis_10y_bp − basis_3y_bp
```

5/7·2/7은 만기 3년과 10년 사이의 5년 지점을 선형보간한 가중치다. 5년 현물은 거래 가능한 중간 선물 레그가 아니라 곡률 설명 기준이다. 교차 베이시스는 완료된 1분 마지막 관측의 최근 60분을 참조하며 최소 20개가 있어야 z-score를 표시한다. 공백을 가로지르는 변화를 만들지 않는다. 관측 반감기는 최근 연속 분봉에 절편을 포함한 AR(1)을 적합해 `−ln(2)/ln(phi)`로 계산하며 `0 < phi < 1`과 10개 이상 관측일 때만 표시한다. 이는 구조적 공적분이나 미래 수렴을 증명하지 않는다.

정수 DV01 패키지의 근사 왕복 호가비용은 `(N3×spread3 + N10×spread10)×1,000,000원`이다. 교차 베이시스 손익분기 bp로 바꿀 때 양쪽 금리가 평균 수준을 중심으로 대칭 이동한다고 가정해 분모를 `(N3×DV01_3 + N10×DV01_10)/2`로 둔다. 대기열·부분체결·시장충격·수수료·현물 carry/repo는 포함하지 않는다. z-score와 현재 평균 이격이 각각 설정 임계값과 비용 배수를 넘으면 `비용 초과 상대가치 괴리 관측`으로만 표시하며 주문 신호가 아니다.

### 5.4 DV01 및 수량

```text
P_T(y) = Σ[i=1..2T] coupon_i/(1+y/2)^i + 100/(1+y/2)^(2T)
coupon_i = 2.5, 마지막 현금흐름에는 원금 100 추가
DV01_KRW = {P_T(y−1bp) − P_T(y+1bp)} / 2 × 1,000,000
exact_3Y = N10 × DV01_10Y / DV01_3Y
rounded_3Y = max(1, round(exact_3Y))
residual = abs(rounded_3Y×DV01_3Y − N10×DV01_10Y)
gross = rounded_3Y×DV01_3Y + N10×DV01_10Y
```

자동 계산은 KRX 표준 조건인 액면 1억원, 연 5% 쿠폰, 반기 지급, 잔존 3년·10년을 사용한다. 중앙차분 결과는 동일 현금흐름의 해석적 가격미분과 자동시험에서 교차검증한다. 대시보드 실행 시 수동 DV01이 모두 비어 있고 최신성 한도 안의 양수 선물수익률 두 개가 있으면 계산하며, 기준 수익률·시각과 함께 표시하고 세션 동안 고정한다. 수동 DV01 쌍은 자동값보다 우선한다. 이는 표준채권의 이론 민감도이지 실제 보유채권, 거래 바스켓, 계좌 또는 포트폴리오 DV01 인증값이 아니다.

자동 실행시점 DV01은 대시보드 세션에만 주입한다. 저장 CSV를 별도 실행하는 `paper_backtest.py`와 `analyze_snapshots.py`는 재현성을 위해 `settings.json`의 수동 DV01 또는 `rv.beta`를 계속 사용하며, 당시 자동값을 별도 저장하지 않은 과거 자료에 현재 DV01을 소급 적용하지 않는다.

Python의 반올림(정확한 .5는 짝수 방향)을 사용한다. 최적 정수 패키지 탐색은 아니며 3Y 최소 1계약 가정도 연구 편의다. 순 DV01 부호, 실제 보유 방향, 포트폴리오 노출은 표시하지 않는다. 가상 정수 패키지 한도와 재생의 소수 beta 패키지는 서로 다른 수량 모델이다.

### 5.5 수동 적정가 비교 및 비용필터

```text
manual_difference = market_mid − manual_fair
comparison_cost = futures_spread/2 + manual_extra_cost
display_net_distance = max(0, abs(manual_difference) − comparison_cost)
mean_distance = abs(current_RV − completed_minute_mean)
estimated_roundtrip = spread10 + beta×spread3 + execution.extra_roundtrip_cost_points
required_distance = estimated_roundtrip × min_edge_to_roundtrip_cost
```

수동 비교에는 현물 레그의 비용·조달·잔존만기 모델이 없다. fair는 시작 시 읽은 정적 값이며 자동 갱신·시점 검증이 없다. `mean_distance`는 기대수익이나 정상화 확률이 아니다. 진입 관측시점의 호가로 왕복비용을 근사할 뿐 실제 청산시점 비용은 모른다. 미입력 비용은 0이며 수수료/시장충격/펀딩이 실제로 무료라는 뜻이 아니다.

## 6. 페이퍼 재생 상태 및 손익

신호 시각 t → pending 의도 저장 → 이후 다음 유효 시각 t+1의 best bid/ask로 가상 체결한다. 새 행의 신호가 기존 pending 의도를 취소하지 않도록, 실행 판단과 새 신호 생성의 의미를 분리한다. 단, 불량 데이터·시각 공백·날짜 전환에서는 pending을 취소한다. 체결이 가능한지 잔량을 검사하지 않으므로 이 방식도 낙관적인 관측 호가 가정이다.

RV high(+1)는 가상 short 10Y 1단위 / long 3Y beta단위, RV low(−1)는 반대다. 반전 시 다음 행에서 청산과 반대 진입이 동시에 발생할 수 있으며 양쪽 비용을 각각 계산한다. 기본 N10=1 단위 연구이며 risk.package_10y_contracts가 실제 재생 수량으로 곱해지지 않는다.

```text
high 가상 손익 = (entry_bid10 − exit_ask10) + beta×(exit_bid3 − entry_ask3)
low 가상 손익  = (exit_bid10 − entry_ask10) + beta×(entry_bid3 − exit_ask3)
gross_mid = −state×(exit_RV − entry_RV)
crossing_cost = gross_mid − bidask_PnL
net = bidask_PnL − configured_extra_roundtrip_cost
```

단위는 synthetic points다. 원화 실현손익·수익률·샤프·증거금 수익률은 계산하지 않는다. 소수 계약 가정과 실제 정수 수량의 차이가 있어 단순 금액 환산만으로 실제 포지션 성과가 되지 않는다.

데이터 끝·공백·오류·신호 준비 해제 시 남은 가상 포지션은 `unclosed_mark_only`로 기록한다. 이때 `exit_utc`와 `net_pnl_points`는 비우고 `mark_utc`, `mark_net_pnl_points`에 마지막 관측 평가만 남긴다. 이는 실제 포지션 청산 명령이나 복구 가능한 계좌 장부가 아니다. 이후 정상 구간 연구는 새 가상 에피소드로 시작한다. 집계 손익은 `status=closed`만 포함한다.

출력은 `open('x')`로 새 파일만 생성하며 기존 보고서를 덮어쓰지 않는다. BAT는 임의 접미사 파일을 생성한다. 구버전 `paper_trades.csv`는 보존하며 현행 성과와 섞지 않는다.

## 6A. 가격 알림과 외국인 수급 추정

```text
선물 체결가차(pt) = 10Y trade price − 3Y trade price
현물 금리차(bp) = (10Y cash yield[%] − 3Y cash yield[%]) × 100
```

알림은 `above`, `below`, `between` 조건을 지원한다. 최초 조건 충족 뒤 confirmation_seconds 동안 유지되어야 발생하며, 발생 후 비활성화된다. 기준값에서 hysteresis만큼 이탈해야 재무장하고 cooldown_seconds도 경과해야 한다. 파일 최초 warm-up 행, 지연/미래 수집시각, 연결된 원천시각이 오래되었거나 두 레그 시각 차이가 큰 경우에는 알리지 않는다. 원천시각이 연결되지 않은 현재 상태에서는 수집시각만 검사하므로 RTD 자체 동결은 탐지하지 못한다.

알림 출력은 Windows `FlashWindowEx`의 작업표시줄 점멸 5회, 620Hz·90ms·기본 peak 6%의 생성 WAV, 화면 왼쪽 아래의 비모달 알림 팝업이다. 팝업은 입력 초점을 강제로 가져오지 않고 제목·테두리가 700ms마다 점멸하며 확인할 때 닫힌다. 새 알림은 기존 팝업을 교체한다. 이는 외국인 가격대 지도의 `크게 보기` 창과 별개다. 소리는 별도 daemon thread에서 재생한다. 알림은 관찰 기능이며 주문과 연결되지 않는다.

외국인 추정치는 누적 매수·매도 증가량을 직전 관측 이후 발생한 수량으로 보고 현재 체결가/선물수익률을 대용가격으로 사용한다. 시작 시 기존 누적량은 버리고 baseline만 설정한다. 각 측의 가격·수익률 추정 평균은 증가수량 가중평균이며 가격은 기본 0.02pt 구간으로 집계한다. 누적량 감소나 세션 변경은 당일 추정 이력을 초기화한다. 시각 역행·10초 초과 공백·입력 불량은 이전 관측 이력과 아직 시간창 안에 있는 수급을 보존하지만 연속성 기준을 다시 시작하며, 공백 중 누적 증가분은 가격에 배정하지 않는다. 참가자 체결원장·거래대금·개별 체결시각이 없으므로 실제 외국인 평균체결가, 보유원가, 미결제약정 원가로 표현하지 않는다.

### 6A.1 지금 수급과 가격 요약 (2026-10-29)

- `dashboard_widgets.py`는 상단 가격 카드 아래에 3년·10년 두 요약 카드를 배치한다. 모든 탭에서 확인할 수 있으며 표제, 최근 5분 요약문, 수치 근거를 분리한다.
- `flow_brief.foreign_flow_brief`는 기존 `ForeignFlowTracker.summary()`의 5분창을 받아 순수 문자열 변환을 수행한다. `5분 순매수 = 매수 증가량 합 − 매도 증가량 합`, `가격 변화 = 창 내 마지막 체결가 − 첫 체결가`의 부호를 독립적으로 읽어 `외국인 순매수 · 가격 하락` 등의 문구를 만든다. 0 판정 허용오차는 1e-9다. 확대·가속·인과관계·미래 방향으로 해석하지 않는다. 기존 창은 기준점 행 이후의 첫 유효 관측부터 가격변화를 계산하므로 정확히 5분 전 체결가와의 차이와는 관측 간격만큼 다를 수 있다.
- 수치 근거는 현재 체결가(pt), 5분 가격변화(pt), 5분 순매수(계약), 당일 누적 순매수(원천 누적 매수−매도), 5분 증가수량 가중 매수·매도 추정가격이다. 당일 누적과 최근 5분은 서로 다른 값이며 부호가 반대일 수 있다. 추정가격 기준 현재가 위치는 소수 셋째 자리 표시 해상도에 맞춰 차이 0.0005pt 이상이면 위, -0.0005pt 이하면 아래, 나머지는 부근으로 표시한다. 매수/매도 증가량이 없으면 해당 추정가격은 `—`다.
- 5분 연속 관측 전에는 방향 표제를 보류하고 `관측 중 (x/5분)`으로 표시한다. 공백 이후에도 창 안의 기존 관측량은 유지되므로 `5분창(부분)`으로 표시하며 재개 후 x분간 신규 수급으로 오인시키지 않는다. 수집 지연·복원 중에는 현재 요약을 보류한다. 외국인 누적량·체결가 유효성과 연결된 외국인/체결 원천시각도 검사한다. 원천시각 미연결 시에는 기존 정책대로 수집시각만 사용하며 한계를 화면에 표시한다.
- `Dashboard._render_overview`에서 만기별 수급 요약을 한 번 계산하여 요약 카드와 기존 외국인 상세 탭이 공유한다. 추가 CSV 스캔, Excel COM 호출, 타이머, 외부 의존성은 없고 `ValueLabel`이 변경된 문구만 갱신한다. 기존 신호·알림·위험 계산에 요약문을 입력하지 않는다.
- 검증: 최근 순매수/당일 순매도 동시 발생, 수급·가격 방향 엇갈림, 공백 후 부분 관측, 원천시각 지연·오류, 0 누적량·체결가 결측, 만기별 미연결, 요약 공유 및 데이터 소실 시 화면 초기화를 포함해 전체 87개 시험을 통과했다. 모의 관측 10,000회에서 기존 수급 요약 생성까지 포함한 카드당 처리시간은 평균 약 0.03ms였다. Excel/실시간 UI 전체 성능 측정값은 아니다.

### 6A.2 외국인 가격대 지도 (2026-10-29)

- 외국인 탭 최상단에 3년·10년 가격대별 가로 막대를 배치하고, 기존 수치 상세는 아래에 유지한다. `크게 보기`는 두 차트를 나란히 담은 비모달 창을 연다. 같은 창이 이미 있으면 앞으로 가져오며 주 대시보드와 모드(`gross`/`net`)를 공유한다. 주 창 종료 시 함께 정리된다.
- 원천은 `ForeignFlowTracker.buy.bins`와 `sell.bins`다. 매수/매도 증가분을 당시 시장 체결가의 구간에 배정한 기존 추정치를 그대로 시각화한다. 최초 관측 이전 누적량이나 공백 중 수량을 새로운 가격에 소급하지 않는다. 당일 CSV 복원 경로를 그대로 사용하며 화면은 당일 관측 누적 분포다. 최근 5·15·60분 분포나 실제 외국인별 체결가격 분포로 표현하지 않는다.
- `ForeignFlowTracker.price_profile()`은 가격별 `(하한, 매수증가 관측량, 매도증가 관측량)` 불변 tuple과 합계를 반환한다. 내부 버전은 실제 수량 증가 또는 초기화 때만 변경되고, 정렬·복사 결과는 캐시한다. heartbeat와 일시 pause는 기존 분포를 바꾸지 않는다. 기존 `summary()`·신호·알림 계산 및 CSV 스키마는 변경하지 않는다.
- `group_price_profile()`은 기존 가격 구간을 정수 인덱스로 환산하고 전체 최저~최고 가격 범위가 최대 12개 행에 들어오도록 기본 구간 폭의 정수배로 합친다. 중간 빈 구간도 유지한다. 표시 상위 N개만 선택하거나 관측량을 버리지 않으며 병합 전후 매수·매도·차분 총합을 보존한다. 표시된 집중 구간은 병합 후 구간 기준이고 폭을 차트 아래에 표시한다. 구간 경계는 `[하한, 상한)`이다.
- `gross`는 동일 계약에서 매도(왼쪽 주황)·매수(오른쪽 청록)를 공통 최댓값으로 정규화한다. `net`은 관측 매수−매도의 절댓값 최댓값을 기준으로 순매도는 왼쪽, 순매수는 오른쪽으로 그린다. 두 모드의 오른쪽 숫자는 관측 순매수다. 3년·10년의 축은 독립적이며 화면에도 표시한다. `net`은 잔고·미결제 포지션이 아니다.
- 상단에 표시 구간별 매수·매도 최다 관측 가격대 및 계약 수를 표시한다. 현재 체결가 구간은 금색 배경과 구간 내 실제 위치에 대응한 점선으로 표시하고, 범위 밖 가격은 위/아래 안내로 남긴다. 체결가가 결측/비양수/원천시각 지연이면 현재가 표시를 보류한다. 수집 지연·수급 pause 중에는 기존 분포를 유지하고 갱신 대기 상태를 표시한다.
- Canvas 위 마우스 툴팁은 가격 구간 경계, 매수·매도 증가 관측량, 관측 순매수, 당일 관측 매수 대비 구간 비중을 표시한다. 툴팁도 Canvas 항목으로 그려 별도 팝업이나 입력 초점 이동을 만들지 않는다.
- 기본 데이터 변화에 따른 재그리기는 최대 2초에 한 번으로 제한한다. 모드·최신성 변경은 즉시, 창 크기 변경은 120ms 지연 후 캐시로 다시 그린다. 예약은 위젯당 하나이며 파괴 시 취소한다. 데이터·현재가·상태가 같으면 재그리기를 생략하고 외국인 탭이 비활성이고 큰 창도 닫혀 있으면 가격 분포 스냅샷을 요청하지 않는다. 큰 창이 열리면 다른 탭에서도 같은 대시보드 갱신 루프로 업데이트한다. 추가 Excel COM·CSV 전체 읽기·외부 차트 의존성·별도 수집 타이머는 없다.
- 검증: 기존 96개를 포함해 전체 103개 시험 통과. 증분 배정·캐시 무효화·과거 스냅샷 불변성·공백 제외·넓고 성긴 가격 범위의 총량 보존·소수 경계·비활성 탭 조회 생략·현재가 지연 억제·큰 창의 독립 표시를 검증했다. 모의 UI에서 매수/매도 보기, 순매수 전환, 현재가, 마우스 툴팁 및 종료를 확인했으며 최종 검수 창의 callback 오류는 0건이었다. 실제 외국인별 체결원장과의 일치 검증은 아니다.

## 6B. 당일 10Y–3Y 스프레드 차트

`spread_chart.py`와 `KTB_10-3스프레드_그래프.bat`은 기존 대시보드와 독립된 경량 조회 도구다. BAT는 `spread_chart_launcher.py`를 통해 수집기를 백그라운드로 시작하고 `collector.lock`을 통해 중복 기록자를 방지한다. 기존 수집기가 이미 있으면 새 수집기를 사용하지 않고 기존 기록자를 따른다. 그래프 창 종료 시 BAT가 시작한 자식 수집기만 종료한다.

차트 입력·집계 규칙은 다음과 같다.

- 현재 KST 거래일의 `snapshots_enhanced_YYYYMMDD.csv`만 읽는다.
- 각 KST 분의 마지막 유효 관측을 사용한다. 분 사이 값은 연결·보간하지 않는다.
- `cash_spread_bp`·`futures_yield_spread_bp`가 비어 있으면 각각 `(10Y−3Y)×100` 원천 금리·수익률로 재계산한다.
- 상단 큰 카드는 현물 3년 수익률, 현물 10년 수익률, 선물 10년−3년 수익률차로 구성한다. 별도의 선물 3년·10년 카드로 중복 표시하지 않는다.
- 상단 작은 카드는 각 선물의 외국인 누적 순매수 `foreign_buy−foreign_sell`를 계약으로 표시한다.
- 하단 막대는 각 만기별 누적 순매수의 전 분 대비 차분을 1분 수급 변화량으로 표시한다. 3Y와 10Y는 서로 다른 색상과 막대로 분리한다.

- 화면 크기 변경은 120ms 지연 후 캐시만 다시 그린다. 관측값 변화가 없는 갱신은 차트 재생성을 생략하고, 시간축 계산은 각 시각을 한 번만 파싱한다. 외부 차트 라이브러리는 추가하지 않았다.
- 검증: 추가 행·불완전 행·파일 축소·전체 재읽기 회귀시험 포함 81개 테스트 통과. 개발 PC의 당일 74분 파일 측정에서 최초 집계 약 98ms, 추가 행 없는 재확인 약 1.37ms 및 재읽기 0바이트였다. 최초 집계도 작업 스레드에서 처리한다. 이 수치는 해당 시점 파일 측정이며 장중 전체 UI 부하 보장은 아니다.

## 8. 저장·성능·오류 처리

수집 기본 1000ms, 허용 100~2000ms. 정상 관측과 단순 시세 무효는 매 루프 시작시각 기준으로 다음 읽기까지 최소 간격을 맞춘다(Excel 읽기가 설정 간격보다 길면 추가 대기 없음). COM 호출 실패는 기존 sheet 객체로 0.15초·0.35초 후 두 번만 내부 재시도하며, 성공하면 느린 재연결 상태로 전환하지 않는다. 세 번 모두 실패한 `ExcelConnectionUnavailable`(workbook/시트 미발견, Excel/COM 읽기 예외)만 `PollSchedule`이 오류 감지 후 3초→4초→5초(상한 5초)를 실제로 기다렸다가 재시도한다. 이때 sheet 캐시를 버려 다음 외부 시도에서 workbook과 시트를 다시 찾는다. 기본 호가 `C2:O11`과 추가 RTD 블록 실패는 오류 문구로 구분한다. 첫 정상 스냅샷부터 설정된 정상 간격으로 돌아간다. 0·공란·비정상 호가처럼 읽기는 됐지만 데이터가 유효하지 않은 `FeedUnavailable`은 연결 오류와 구분하며 정상 간격으로 재확인한다. 오류 메시지는 같은 문구를 60초 이내 반복 출력하지 않고 KST 오류 시각과 다음 재시도 간격을 `launcher.log`에 남긴다. 이 조절은 Python의 Excel 읽기 빈도만 바꾸며 공급자 RTD 구독/갱신 주기를 제어하지 않는다. 1초 사이 잠깐 나타난 가격은 관측되지 않을 수 있다.

변동 행 또는 5초 heartbeat 저장. CSV flush/SQLite commit 기본 1초. 강제 종료/정전 시 미반영분 유실 가능하며 CSV와 SQLite 간 원자적 트랜잭션은 없다. SQLite 열은 현재 TEXT다. 운영용 스키마 버전·인덱스·중복키·보존주기·파일 회전은 미구현이다.

CSV/SQLite 기존 열 순서가 예상과 다르거나 CSV 마지막 줄이 불완전하면 이어쓰기를 거부한다. 자동 변환·삭제하지 않는다. 오류 시 새 출력 폴더를 사용하거나 백업 후 별도 복구해야 한다. 여러 수집기를 같은 폴더에 동시에 실행하지 않는다(프로세스 잠금 미구현).

UI는 KST 오늘 날짜의 CSV만 선택한다. 시작 시 마지막 1MiB에서 최신의 완전한 행을 역순 탐색해 신선한 선물수익률 쌍이 있으면 자동 DV01과 고정 beta를 먼저 구성한다. 그 뒤 오늘 파일을 500행 단위로 읽어 외국인 수급과 동일 beta의 변동성/RV 분석창을 복원한다. 최신 행이 오래됐거나 수익률이 0·공란이면 자동 계산하지 않고, 새 정상 행이 들어올 때 다시 시도한다. 복원 중 동일 날짜의 10초 초과 공백은 관측 이력을 삭제하지 않고 연속성만 끊는다. 따라서 공백을 가로지르는 RV 변화·외국인 증가량은 만들지 않으며, 1분 변동성은 실제 인접 분 변화만 사용한다. 복원 중 과거 알림은 발생시키지 않고 과거 합의 신호 상태도 완료 시 폐기해 새 관측부터 다시 확인한다. 금리차 위치·호가압력·수동 적정가 등 다른 탭의 상태는 과거 행으로 복원하지 않는다. 복원 중 추가된 행도 따라잡는 동안 알림을 재생하지 않는다. 이후 일반 tail은 한 번에 최대 1MiB씩 추가분을 읽고 마지막 불완전 줄은 다음 읽기까지 보관한다. 파일 축소·파일 식별자 변경 시 재준비한다. 같은 inode에서 크기를 유지하며 내용을 덮어쓰는 경우까지 탐지하지 않는다.

UI는 데이터 지연/미래 시각이면 현재 신호 사용 금지를 표시한다. 읽기·형식 오류는 기존 상태를 초기화하고 오류를 표시한다. 과거 지표 숫자는 참고 화면에 남을 수 있으나 활성 신호가 아니다. 수집시각이 신선해도 원천 RTD가 동결된 상태일 수 있으며 이 문제는 원천 heartbeat/시각 없이는 해결되지 않는다.

수집기가 잠깐 거부한 입력은 CSV에 기록되지 않는다. 따라서 10초 이하의 원천 오류 이력이 신호 엔진에서 보이지 않을 수 있다. 과거 CSV 안에 직접 존재하는 불량 행을 초기화하는 것과 공급자 오류 이력의 완전한 동기화는 다르다. 공급자 품질 이벤트/세션 식별자를 로그에 추가하는 것은 후속 작업이다.

저부하 설계는 bounded deque, 변경 기반 EMA, 이벤트 통계 캐시, COM 일괄 읽기, 증분 UI, 파일 핸들 재사용으로 구현했다. 실제 Excel CPU/메모리·오랜 장중 가동·복구 지연 수치는 이번에 측정하지 않았다.

## 9. 실행과 재현

프로젝트 폴더에서 실행한다. `output`은 존재하지 않는 새 파일명을 사용한다.

```powershell
.\.venv32\Scripts\python.exe -m unittest discover -p 'test*.py'
.\.venv32\Scripts\python.exe -m py_compile dashboard.py dashboard_widgets.py market_extensions.py flow_brief.py book_pressure.py foreign_profile.py spread_chart.py spread_chart_feed.py
.\.venv32\Scripts\python.exe audit_snapshots.py data/snapshots_with_trades.csv --settings settings.json --output data/audit_new.json
.\.venv32\Scripts\python.exe paper_backtest.py data/snapshots_with_trades.csv --settings settings.json --output data/replay_new.csv
```

실시간 실행은 Excel 연결을 사용자가 먼저 확인하고 `KTB_모니터_시작.bat`을 한 번 실행한다. BAT는 `pythonw.exe`로 `monitor_launcher.py`를 시작하므로 별도 콘솔을 유지하지 않는다. 실행기는 `data/monitor_launcher.lock`에 비차단 Windows 파일 잠금을 잡아 같은 폴더의 중복 통합 실행을 막는다. 수집기는 콘솔 없이 자식 프로세스로 실행되고 stdout/stderr는 `data/launcher.log`에 기록된다. 로그가 시작 시점에 2MB 이상이면 기존 `launcher.log.old`를 교체하고 현재 로그를 그 이름으로 옮겨 무제한 누적을 막는다. 1초 뒤 수집기가 살아 있으면 대시보드를 시작한다. 대시보드에는 별도의 `data/dashboard.lock`을 적용한다. 독립형 스프레드 그래프가 먼저 `collector.lock`을 보유한 경우 통합 BAT는 수집기 중복 오류로 종료하지 않고 기존 수집기에 연결해 대시보드만 추가로 시작한다. 따라서 그래프와 기존 대시보드는 동시에 열 수 있고, 대시보드가 먼저 실행 중이면 그래프는 같은 수집기를 사용한다. 대시보드가 종료되면 통합 실행기가 시작한 수집기를 정상 종료 요청하고 5초 안에 끝나지 않을 때만 강제 종료한다. 잠금은 프로세스가 종료되면 운영체제가 해제하므로 잠금 파일이 남아 있어도 실행 상태를 뜻하지 않는다.

실시간 COM/RTD 공백은 지연 중에는 신호를 차단하며, 복구 시 공백 전후 변화와 확인 시간을 연결하지 않는다. 다만 같은 거래일의 완료 분봉 관측은 보존하여 짧은 재연결마다 60분 통계창 전체를 초기화하지 않는다.

수집기 자체도 출력 폴더의 `collector.lock`으로 단일 기록자를 보장한다. 통합 실행기 잠금과 달리 CLI로 수집기를 별도 실행해도 동일 출력 폴더에 중복 기록하지 못한다. 잠금 파일은 남아 있어도 운영체제의 프로세스 잠금이 해제되면 다음 실행이 가능하다. 추가 RTD 시트 객체는 유효한 동안 캐시해 매번 workbook·sheet 조회에 필요한 COM 왕복을 줄이고, 무효화되면 다시 연결한다. Excel의 전역 계산 모드와 재시작 후에도 지속될 수 있는 RTD 갱신 간격은 변경하지 않는다.

테스트는 모의 Excel 객체를 사용하며 실시간 데이터 연결 성공을 뜻하지 않는다. 상세 검증 결과와 미완료 항목은 [FINAL_REVIEW.md](FINAL_REVIEW.md), 업무 적용 경계는 [TRADING_SCOPE.md](TRADING_SCOPE.md)를 따른다.

| 호가 재실행 복구 | 새로 실행한 시점부터 이벤트 점수 시작 | 당일 CSV의 시간가중 관측을 복원 | 기존 이벤트 점수는 과거 재생하지 않는다. |
| 외국인 가격대 | 평균·주구간을 긴 텍스트로 표시 | 매수/매도 수평 막대, 순매수 전환, 집중 구간, 현재가, 툴팁, 큰 창 | 기존 가격별 증가량을 시각화한다. |
| 화면 부하 | 텍스트 갱신 중심 | 가격 구간 캐시, 선택된 화면에서만 스냅샷 요청, 2초 재그리기 제한 | 추가 Excel 호출·원시 로그 재검색을 피한다. |
| 기존 별도 스프레드 그래프 | 파일 전체 읽기로 창 조작이 지연될 수 있었음 | 단일 작업 스레드·추가 행 읽기·변경 없는 차트 재생성 생략 | 직전 푸시의 성능 개선분이며 현재 코드에도 포함한다. |

### 10.2 입력 부족·공백·초기화의 의미

| 상황 | 외국인 요약/가격대 | 시간가중 호가 관측 |
|---|---|---|
| 최초 유효 관측 | 누적 수량은 기준점으로만 사용하고 증가량부터 가격에 배정 | 기준점을 만들며 경과시간 0초에서는 평균을 만들지 않음 |
| 5분 창이 덜 채워짐 | 연속 관측 준비 문구와 부분 수급을 표시 | 실제 유효 초수/300초와 각 창의 부분 관측률 표시 |
| 일시적인 긴 읽기 공백 | 추적기 자체는 기존 관측 구간을 남기고 미관측 증가량은 배정하지 않음 | 이미 집계한 구간은 보존하고 공백을 적분하지 않음 |
| 지연된 현재 화면 | 현재 상황 문구/현재가 선을 보류하며 관측 분포는 과거 누적으로 표시 | 마지막 집계시각과 누적 근거를 표시 |
| 입력 불량으로 대시보드 공통 초기화 | 기존 외국인 추적기는 재생성될 수 있음. 모든 예외에서 누적 분포가 무조건 보존되는 설계는 아님 | 새 `preserve_book=True` 경로는 호가 합계를 보존하고 연속성만 끊음 |
| 날짜 변경·파일 재연결 | 당일 파일 선택과 기존 초기화/복원 경로를 따름 | 새 당일 관측을 만들며 이전 날과 합산하지 않음 |
| 수집기가 꺼진 시간 | 기록에 없는 실제 체결가격은 복원할 수 없음 | 기록에 없는 호가 지속시간을 만들어 채우지 않음 |

호가 시간비율은 직전 표본의 유지 가정, 외국인 가격 분포는 누적 증가량과 시장 체결가를 결합한 배정 가정이다. 두 지표는 서로 다른 현상을 측정한다. 미연결 원천시각으로 인한 공급값 동결의 한계도 남는다.

### 10.3 검증 및 성능 수치의 범위

이번 배포 직전 검증 명령은 9장의 unittest discovery와 py_compile이다. 현재 회귀시험은 총 103개이며, 개별 단계에서 기록한 81·87·96개는 당시 시험 수다.

| 시험 파일 | 핵심 검증 내용 |
|---|---|
| `test_flow_brief.py` | 당일 순매도/최근 순매수 공존, 수급과 가격 방향 엇갈림, 부분 관측, 원천시각, 0·결측, 만기 독립 |
| `test_book_pressure.py` | 불규칙 시간 가중평균, heartbeat 간격 불변성, 창 경계 절단, 공백 제외, 날짜/세션/계약 변경, 재구성 동등성 |
| `test_foreign_profile.py` | 최초 누적 제외, 가격별 증가량, 캐시 수명, 이전 스냅샷 보존, 구간 병합 총량 보존, 소수 가격 경계 |
| `test_safety.py` 추가분 | 기존 상세와 요약 공유, 불량 행 뒤 호가 합계 보존, 당일 복원, 비활성 지도 조회 생략, 현재가 지연 억제, 별도 창 갱신 |
| 기존 시험 전체 | 호가 검증, 변동성/RV, DV01, 가격 알림, 공통 수집기 잠금, 별도 스프레드 그래프 등 회귀 확인 |

앞선 모의 성능 검수에서 문장 요약은 카드당 약 0.03ms, 시간가중 호가 집계는 두 만기 합산 행당 약 0.062ms였다. 이 값은 특정 PC에서의 계산 측정이며 Excel·실시간 저장·전체 화면 CPU 사용률이나 연결 무중단을 보장하는 값은 아니다. 큰 지도 모의 화면에서는 보기 전환·현재가·툴팁·종료를 직접 확인했고 최종 callback 오류는 0건이었다.

### 10.4 배포·업데이트·사용

1. 새 모듈 3개(`flow_brief.py`, `book_pressure.py`, `foreign_profile.py`)와 새 시험 3개를 기존 변경 파일과 함께 배포한다. 새 BAT나 별도 설치 과정은 추가하지 않는다.
2. 기존 `settings.json`, RTD 시트 연결, CSV/SQLite 열 구성은 그대로 사용한다. 사용자 알림 규칙을 변경한 로컬 `extra_settings.json`은 이번 기능 코드와 구분해 보존한다.
3. 실행 중인 대시보드를 닫고 `KTB_모니터_시작.bat`을 다시 실행한다. 오늘 저장된 기록이 있으면 수급·호가·변동성 관측을 복원한 후 새 행부터 표시한다. 통합 실행기가 직접 시작한 수집기는 대시보드 종료 시 함께 종료될 수 있으므로 작업 중 재시작은 이를 고려한다.
4. 상단에서 수급/가격 요약, `호가 · 비용`에서 누적 관측, `외국인 수급`에서 가격대 지도와 `크게 보기`를 확인한다. 별도 스프레드 그래프의 실행 방법은 유지한다.
5. 배포 대상은 기존 `extended` 원격의 `https://github.com/KOJH-archive/ktb_rtd_monitor-Extended-.git`, 작업 브랜치는 `rtd-cleanup-1s-retry`다. 이번 요청은 현재 작업 브랜치 푸시이며 main 병합은 포함하지 않는다.
