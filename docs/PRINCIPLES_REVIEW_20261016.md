# 원래 설계 원칙 재검토 및 UI·부하 점검

점검일: 2026-10-16. 비교 대상은 최초 첨부 프롬프트와 현재 코드다.

## 판정

현재 제품은 RTD 기반 실시간 관찰·연구 도구다. 원래 요구한 **변동성 중심 포지션 사이징 프레임워크는 아직 완성되지 않았다.** 앞서 개발 완료라고 표현한 범위에는 이 핵심 단계가 포함되지 않았으며, 전체 원칙에 충실하게 구현됐다고 판단할 수 없다.

Z-score의 분모인 가격 **수준**의 표준편차와, 보유 패키지의 기간별 **손익 변화** 표준편차는 목적이 다르다. 전자는 현재 가격의 상대적 이탈을 표시하고 후자는 위험 노출과 수량 산출에 필요하다. DV01 비율도 두 종목의 헤지 비율을 정할 뿐, 감당 가능한 전체 패키지 수를 정하지 않는다.

외부 대조: [pysystemtrade PositionSizing 원문](https://github.com/pst-group/pysystemtrade/blob/develop/systems/positionsizing.py)은 자본·목표 변동성과 계약 위험을 별도 입력으로 사용한다. 이 문서의 현재 구현 판정은 해당 원문의 성능 주장을 인용한 것이 아니라 로컬 코드를 비교한 결과다.

## 요구사항과 실제 구현

| 최초 원칙 | 현재 코드의 근거 | 판정 |
|---|---|---|
| 수익 방향 예측보다 위험 노출 관리 | `SignalEngine`은 120 가격 이벤트와 완료 60분 Z-score 중심 | 부분 반영, 신호 관측 비중이 큼 |
| 패키지 손익 변동성 기반 수량 | 위험예산, 일간 변동성 예측, 목표 계약 수 계산 없음 | 미구현 |
| DV01 헤지 및 정수화 후 잔여 위험 | `dv01_package`, `risk_metrics`에서 계산. DV01·한도 기본값은 미입력 | 구현됐으나 입력 필요 |
| 상관관계·공통 금리요인 집중도 | 합성 RV는 두 가격의 동시 움직임을 포함하지만 포트폴리오 상관·집중도 한도 없음 | 미구현 |
| 세 전략에 맞는 위험요인 분리 | 스프레드 관측, 수동 적정가 비교, 호가 압력 보조지표 | 통합 전략별 위험예산 엔진 없음 |
| 비용과 실행 위험 반영 | 호가 왕복비용, 다음 관측 가상 체결 | 부분 반영. 깊이·충격·펀딩·증거금 등 없음 |
| 중장기와 일중 시간척도 분리 | 120이벤트 / 60분. 날짜 변경·10초 초과 공백에 초기화 | 장중만 지원, 수일·수주 기준 없음 |
| 독립 OOS / Walk-forward | 기존 데이터 재생·품질 테스트 | 수익성 검증 미완료 |
| 저부하 의사결정 지원 | 별도 수집기, Tk UI, CSV 증분 읽기, 제한된 이력 | 구현·추가 최적화, 장중 장시간 총부하 미측정 |

`SignalResult.entry_allowed`는 설정된 연구 비용/가상 위험한도 검사 결과다. 위험 입력이 없어도 연구 재생을 허용한다. 실운용 수량 허용 또는 전체 위험관리 통과를 뜻하지 않는다. 이번에 매매 신호의 임계값·방향·가상 체결 규칙은 변경하지 않았다.

## 이번 수정

### 화면

- 상단: 3년·10년 최근 체결가, 선물 가격차(pt), 현물 금리차(bp)를 큰 카드로 표시.
- 첫 탭: 변동성 관측 → 위험예산·수량 구현 상태 → DV01 헤지 → 상대가격 이탈.
- 외국인 수급과 상세 호가·비용을 별도 탭으로 배치하고 긴 문장은 줄바꿈.
- 한글 UI, KST 수집시각, 숫자 정렬·천 단위 구분, 화면이 작으면 탭 내부 스크롤.
- 지연·오류·기록 복원 중에는 상태를 표시. 오류 이후 오래된 수치가 남지 않게 초기화.
- 사용자가 저장한 현물 금리차 알림 31bp 이하 / 34bp 이상 설정은 변경하지 않음.

### 관측 변동성

완료된 분별 마지막 관측값에 대해 다음을 계산한다.

```text
L[t] = mid10[t] - beta * mid3[t]
dL[t] = L[t] - L[t-1]   (두 완료 분의 간격이 정확히 1분일 때만)
observed_sigma = sample_standard_deviation(dL), ddof=1
```

기본 60개 완료 분에서 최대 59개 1분 변화가 나온다. 현재 진행 중인 분은 제외하며, 변화가 0인 분은 포함하고 누락된 분 사이를 보간하지 않는다. 기본 창이 모두 차고 연속 변화 표본이 충분할 때만 준비 완료로 표시한다. 가격 수준 분산과 독립적으로 표시한다.

이는 **합성 포인트 단위 장중 관측치**다. 실제 정수 헤지 패키지의 원화 일간 손익, 미래 변동성 예측, 현물 커브 변동성, 연율 목표 위험, 권장 수량을 의미하지 않는다. 0이 관측되더라도 위험이 없다는 뜻이 아니다. 확인된 원/포인트 승수·정수 수량·충분한 기간별 손익 이력이 있어야 다음 단계로 연결할 수 있다.

### 부하

- 완료 분 통계는 분이 완료되거나 창에서 제거될 때만 재계산.
- 같은 텍스트/색상은 Tk 위젯에 다시 전달하지 않음.
- 시작 시 기록 처리를 한 번에 최대 250행 / 계산 시간 목표 20ms로 나눔. 대기 중에는 25ms, 정상 상태에서는 500ms 후 다음 콜백. 파일 읽기·파싱·화면 배치는 이 계산 시간 목표에 포함되지 않음.
- 초기 파일 읽기 상한 16MiB / 최근 20,000행, 이후 1MiB 단위 읽기 유지.
- 창 크기/줄바꿈의 자기 참조로 생긴 UI 반복 갱신을 실제 창 검사에서 발견하여 컨테이너 기준으로 변경.
- 웹 런타임, 차트 엔진, 애니메이션, 추가 외부 패키지 없음. 수집기 polling 250ms 유지.

Python 3.12.13, 32bit 환경에서 수행한다.

```powershell

.\.venv32\Scripts\python.exe benchmark_dashboard.py
.\.venv32\Scripts\python.exe preview_dashboard.py --demo --seconds 90
```

동일한 결정적 모의 데이터 20,000행(초당 4행, 약 83분)을 사용한 계산 엔진 비교:

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| CPU 초 | 11.594 | 9.125 |
| 경과 초 | 11.941 | 9.194 |
| 행당 CPU ms | 0.5797 | 0.4562 |

이 1회 비교에서 CPU 시간은 약 21% 감소했다. Excel/COM, 파일 읽기, 화면 그리기는 포함하지 않는다. PC 환경에 따라 수치는 달라지며 0% 부하를 뜻하지 않는다.

UI 대기 부하와 최종 회귀시험 결과는 아래 추가 기록을 따른다. 검수 창은 모의 데이터임을 제목에 표시하며 소리·작업표시줄 알림과 설정 저장을 차단하고 자동 종료한다.

## 원래 원칙을 완성하기 위한 다음 개발 범위

1. 계약월·가격 승수·DV01·거래일이 확인된 패키지 원화 손익 시계열을 마련한다. 일간 위험을 분봉의 단순 제곱근 환산으로 대체하지 않는다.
2. 단순한 일간 EWMA 등 기준 변동성 모델과 충분한 이력·하한·급등 반응 규칙을 고정한다. 장중 관측 변동성은 별도의 보조 지표로 유지한다.
3. 전략별 목표 일간 손익 변동액 / 1개 패키지의 예상 일간 손익 변동액으로 수량 초안을 계산한다.
4. 정수 계약 변환 후 잔여 DV01·총 위험·집중도·증거금·최대손실·비용·유동성 제한을 다시 검사하고, 입력 부족이면 수량 산출 불가로 표시한다.
5. 실제 주문 없이 목표/현재 수량 차이를 관찰하고, 시간순 OOS 및 비용 스트레스를 거쳐 유효성을 평가한다.

이 단계는 화면 디자인 변경이나 기존 연구 beta 조정만으로 완료되지 않는다. 사용자의 기존 운용 의도대로 자동 주문은 범위에 포함하지 않는다.
