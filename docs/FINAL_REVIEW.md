## 2. 실제 실행한 검증

환경: Python 3.12.13 32bit. 설치 버전: xlwings 0.33.22, pywin32 312. Excel 연결은 모의 객체로 검사했으며 실제 COM 세션은 기동하지 않았다.

- `python -m unittest -v`: 39개 통과(기존 수학 시험 16개 + 안전성·확장 시험 23개).
- `python -m compileall -q ...`: 수정된 주요 8개 모듈 구문 검사 통과.
- `git diff --check`: 공백 오류 없음. Git의 LF→CRLF 안내는 기능시험 결과와 무관.
- 전체 CSV 품질 감사 및 공통 엔진 재생: 완료. 기존 데이터/보고서 덮어쓰기 없음.
- 실제 시세 연결·Tkinter 육안 배치·장시간 부하·장중 장애 복구·공급자 동결 탐지: 이번 검증에 포함되지 않음.

시험 범위에는 설정 오류, 비유한 수, 잠김/역전 호가, 완료 분 평균의 미래값 비참조, 제한된 메모리, heartbeat EMA 불변, 신호 시간확인, 위험 위반 차단, CSV 부분 줄/CRLF/축소, 스키마 보존, 단일 COM 읽기, 다음 행 체결, 미청산 구분, 공백 시 pending 취소가 포함된다. 추가로 화면 객체를 모의해 지연/미래시각 신호 차단, 오류 후 상태 초기화, 불량 행 뒤 정상 행 처리도 검사했다. 모의 체결·화면 시험은 실제 시장 체결 또는 육안 UI 검증이 아니다.

## 4. 수정 후 재생 결과

```text
rows=120102, invalid_rows=166, resets=16
max_fast_samples=120, max_completed_minutes=30
ready_rows=0, entries=0, closed=0, unclosed=0
pending_at_end=False
```

결과 CSV: [paper_trades_audit_20261015.csv](../data/paper_trades_audit_20261015.csv). 거래가 없으므로 헤더만 있다. 이후 진단 카운터를 추가한 코드로 다시 실행해 동일한 0건과 최대 준비 표본 수를 확인했다.

해석: 품질 규칙을 지키면서 연속으로 쌓인 완료 분봉이 최대 30개라 60분 조건에 도달하지 못했다. **0건은 수익성 실패도 성공도 아니다. 성과를 평가할 신호 표본이 없다는 뜻이다.** 조건을 완화해 거래를 만들어내거나 결과에 맞춰 임계값을 최적화하지 않았다.

구버전 `data/paper_trades.csv`는 동일 행 체결·구버전 분봉/확인 규칙·데이터 품질 처리를 사용한 산출물이다. 보존은 하지만 현재 전략 성과·실거래 적합성의 근거로 쓰지 않는다. 이전에 기능 완료 또는 실체결 가능 손익처럼 표현했다면 이 보고서의 제한된 판정으로 대체한다.

## 5. 여전히 남은 제한과 우선순위

| 우선순위 | 미완료 | 완료를 판단할 증거 |
|---|---|---|
| P0 실거래 사용 전 | 공급자 시각/heartbeat/계약월/시장상태, 짧은 품질오류 로그 | 원천 피드 동결·잠김 호가·데이터 공백 원인 분리, 각 상태의 재현시험 |
| P0 실거래 사용 전 | 포지션·실시간 민감도·계좌 한도 | 실제 수량과 사내 위험 시스템의 수치 대사 및 승인 |
| P1 연구 성과 주장 전 | 충분한 정합 데이터·장기 기준·OOS | 사전 고정 파라미터, 시간순 독립 검증, 국면/비용 스트레스 결과 |
| P1 체결 가능성 주장 전 | 정수 수량·depth·지연·슬리피지·레그 리스크 | 체결 이력 대사, 현실적인 가상 체결 모델 |
| P1 베이시스 기능 완성 전 | 바스켓 이론가·repo/캐리·시점 있는 입력 | 독립 가격평가와 비교, 실제 현물 헤지·비용 검증 |
| P2 운영 배포 전 | 잠금·회전·보존·복구·재현 환경 고정 | 장시간 운영시험, 재시작/동시실행/디스크 장애시험 |

추가 위험: 현재 자정 초기화는 거래소 야간 세션 경계가 아니다. 단순 이벤트 요약 CLI는 공통 엔진의 모든 품질/연속성 검사를 대신하지 않는다. UI 시작 시 최근 20,000행만 복원하므로 전체 이력을 재생한 결과와 워밍업 상태가 다를 수 있다. 반올림 위험 패키지와 소수 beta 연구 손익은 같은 실포지션이 아니다.

## 6. 보존 및 변경 범위

초기 점검에서는 원본 Excel, 기존 CSV/SQLite, 기존 `paper_trades.csv`를 수정하거나 삭제하지 않았다. 이후 사용자가 동일 workbook에 `추가RTD` 시트를 직접 추가했으며, 코드는 그 셀을 읽도록 연결했지만 workbook 자체를 다시 편집하지 않았다. 실제 주문·외부 서비스는 시작하지 않았고 커밋/푸시도 하지 않았다. 이 작업은 완료된 기관 트레이딩 시스템을 선언하는 것이 아니라, 현재 구현의 경계를 명확히 하고 오해를 만들던 계산·표시·검증을 수정한 단계다.
