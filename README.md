# KTB Excel RTD Monitor

## 현재 판정 (2026-10-15)

관찰·연구용 프로토타입입니다. 기관 실거래용 승인 신호, 현물 베이시스 엔진, 계좌 통합 리스크 시스템이 아닙니다. 최종 감사에서 보유 120,102행에 품질 규칙을 적용한 결과 완료 분봉은 최대 30개였고, 기본 60분 준비조건을 충족한 연구 신호/가상 거래는 0건입니다. 기존 페이퍼 성과를 검증된 수익으로 해석하지 마세요.

- [운용사에서 가능한 일과 불가능한 일](docs/TRADING_SCOPE.md)
- [개발명세서: 기술스택·논리구조·계산식·설정](docs/DEVELOPMENT_SPEC.md)
- [최종 점검·리팩토링·검증 결과](docs/FINAL_REVIEW.md)

한국 국채선물 3Y/10Y의 Excel RTD 실시간 호가와 시장 체결가를 Python으로 수집·분석하는 관찰용 프로토타입입니다. 자동주문·주문 API·실거래 기능은 포함하지 않습니다. 수동 주문 운영에 맞춰 Excel은 기본 1초마다 읽고, 중복 호가는 5초 heartbeat로 축약하며 CSV·SQLite는 1초 단위로 묶어 저장합니다. Excel 연결·읽기 오류가 연속되면 3→4→5초(최대 5초) 간격으로 재시도하고, 정상 관측이 돌아오면 1초로 복귀합니다.

## 빠른 실행

1. 32비트 데스크톱 Excel에서 `국채선물 호가창.xlsx`를 엽니다.
2. CheckExpert RTD 값이 표시되는지 확인합니다.
3. `KTB_모니터_시작.bat`을 한 번 더블클릭합니다.

통합 실행기가 수집기를 보이지 않게 시작한 뒤 대시보드를 엽니다. 대시보드를 닫으면 수집기도 함께 종료됩니다. 중복 실행을 시도하면 새 수집기를 만들지 않고 이미 실행 중이라는 안내를 표시합니다. 실행 오류와 수집 상태는 `data\launcher.log`에 기록합니다.

현재 workbook의 `추가RTD!B1:B10`에는 현물 3Y/10Y 체결수익률, 3Y/10Y 외국인 누적 매수·매도, 선물 체결가·선물수익률이 연결되어 있습니다. 추가 RTD 금리나 선물 체결가가 일시적으로 0·공란·오류 값이면 해당 지표와 관련 차이는 `N/A`로 표시하고 정상 호가 수집은 계속합니다. 유효한 값이 들어오면 재시작 없이 다시 계산합니다. 외국인 누적 거래량의 0은 유효한 값입니다. 다만 핵심 선물 호가의 0은 유효한 시세로 보지 않으므로 호가 자체가 잘못된 경우는 수집을 보류합니다. 수집기는 KST 날짜별 `data\snapshots_enhanced_YYYYMMDD.csv`와 같은 이름의 SQLite에 저장합니다. 대시보드는 **오늘 날짜 파일의 외국인 수급 기록만** 시작 시 복원하고, 일반 신호·알림은 과거 기록을 재생하지 않고 새로 추가되는 행부터 계산합니다. 새로 실행하면 빠른 창과 60분 신호 창은 다시 채워집니다.

## 대시보드 화면

상단에는 3년·10년 선물 체결가, 선물 수익률 차, 현물 금리차가 표시됩니다. 선물 수익률 차는 `10년 선물 수익률 − 3년 선물 수익률`을 bp로 바꾼 값입니다. 기존 선물 **가격차(pt) 알림**은 변경하지 않았습니다. 아래 탭은 `금리차 위치 / 외국인 수급 / 변동성 · 위험 / 호가 · 비용` 순서입니다. 코드 변경을 적용하려면 대시보드를 닫아 통합 실행기를 종료한 뒤 `KTB_모니터_시작.bat`을 다시 실행합니다.

대시보드의 **금리차 위치** 탭은 `추가RTD` 현물 3년·10년 체결수익률로 10년−3년 차이(bp)를 계산합니다. 완료된 분의 마지막 관측값을 5분·60분 기준으로 삼아 평균 대비 거리와 Z-score를 표시하고, 현재값의 5분·15분 변화를 보여줍니다. 해당 분 수가 채워질 때까지 준비 중이며, 누락·지연 데이터 뒤에는 다시 준비합니다. 60분 기준은 장중 관측용입니다.

**외국인 수급** 탭은 당일 저장된 관측 기록에서 누적 매수·매도 추정가격과 주구간을 복원하고, 최근 5·15·60분의 순매수(매수 증가량−매도 증가량)·증가량 가중 매수/매도 추정가격, 최근 1분 순매수 속도(계약/분), 최근 5분의 수급·선물가격 방향을 표시합니다. 창이 아직 차지 않았으면 부분 관측으로 표시합니다. 같은 초의 관측은 초 단위 버킷으로 묶어 계산량을 제한하며 경계에서 최대 약 1초의 포함 차이가 있을 수 있습니다. 이 값들은 공급자의 누적 수량과 관측 당시 공통 선물 체결가를 결합한 추정치이며 실제 외국인 체결원가·순포지션이나 인과적 매매 신호가 아닙니다. 원천 RTD 시각이 연결되지 않은 항목은 수집 시각 기준입니다.

`변동성 · 위험` 탭에는 완료 1분 RV 변화의 관측 표준편차와 별도의 일별 현물금리 기반 위험예산 연구 수량이 표시됩니다. 연구 수량은 아래 입력이 충족될 때만 계산합니다. 선물 실현손익이나 실제 운용 수량으로 해석하지 마세요. 초기 설계 원칙과 장중 지표의 차이는 [원칙 재검토](docs/PRINCIPLES_REVIEW_20261016.md)를 참고하세요.

## 가격대 알림

대시보드의 `가격 알림 설정`에서 다음 기준을 `이상`, `이하`, `구간`으로 설정할 수 있습니다.

- 10년−3년 선물 체결가 차(pt)
- 10년−3년 선물 수익률 차(bp): 수익률이 % 단위이면 차이에 100을 곱합니다. 기준값도 bp로 입력합니다.
- 현물 10년−3년 체결수익률 차(bp)
- 3년 또는 10년 선물 체결가

조건이 1초 이상 유지되면 작업표시줄의 대시보드 버튼을 5회 점멸하고 화면 왼쪽 아래에 알림 팝업을 띄웁니다. 팝업의 테두리와 제목 배경은 0.7초마다 깜빡이며 ‘확인 · 닫기’를 누를 때까지 유지됩니다. 표시된 숫자는 알림 발생 당시 값입니다. 새 알림은 기존 팝업을 교체하며, 소리가 켜져 있으면 발생 시 0.09초 길이의 낮은 음량 알림음을 한 번 냅니다. 조건 안에 머무는 동안 새 알림을 반복 발생시키지는 않으며, 설정된 재무장 폭만큼 기준에서 이탈한 뒤 다시 진입해야 재알림됩니다. 지연 데이터에는 알림을 내지 않습니다.

현재 `추가RTD`에는 원천 갱신시각 셀이 없으므로 수집 PC 시각으로 최신 여부를 확인합니다. RTD 공급값 자체가 동결된 경우를 완전히 판별하지 못합니다. 추후 원천 시각 셀을 추가하면 `extra_settings.json`의 시간 항목에 연결할 수 있습니다.

## 외국인 수급 관측 가격대

외국인 누적 매수·매도 수량의 직전 관측 대비 증가분을 그 시점의 선물 체결가와 선물수익률로 가중해 매수·매도별 추정 평균 및 주 관측 가격구간을 표시합니다.

```text
관측 매수 추정가격 = Σ(외국인 누적매수 증가량 × 관측 선물체결가) / Σ증가량
관측 매도 추정가격 = Σ(외국인 누적매도 증가량 × 관측 선물체결가) / Σ증가량
```

당일 첫 관측 이전 누적량은 현재 가격에 소급하지 않습니다. 날짜/세션 변경이나 누적량 감소 시 주구간을 초기화합니다. 10초 초과 공백·잘못된 체결가·지연된 원천시각에서는 이미 관측한 당일 주구간은 유지하되 최근 수급 창을 초기화하고, 공백 중 증가한 수량은 어느 가격에도 배정하지 않습니다. 대시보드 재시작 시 오늘 CSV의 기존 행을 나누어 읽어 외국인 수급만 복원하며 그 과정에서 알림은 발생하지 않습니다. 수집기가 꺼져 기록되지 않은 체결은 복원할 수 없습니다. 참가자별 개별 체결가·거래대금이 없기 때문에 이는 실제 외국인 평균체결가가 아니라 RTD 관측 간격에 의존하는 추정치입니다.

외국인별 실제 체결가·보유원가·미결제 포지션은 현재 연결된 RTD의 투자자 유형별 누적 매수·매도 수량만으로 식별할 수 없습니다. 외국인별 완전한 체결 원장, 시작 잔고 및 계약월별 포지션 자료가 없는 상태이므로 해당 세 값은 화면에서 미제공으로 표시합니다.

## 일별 현물금리 위험예산과 시간순 검증

현물 일별 CSV에는 `date,cash_3y_yield_pct,cash_10y_yield_pct` 열이 필요합니다. 날짜는 `YYYY-MM-DD`, 수익률은 `%` 숫자이며 날짜가 오름차순·중복 없이 있어야 합니다. `settings.json`의 `risk.cash_history_csv`는 로컬 `data/cash_daily.csv`로 설정되어 있습니다. 원본 `기획팀/한국채_금리_조회결과.xlsx`를 읽기 전용으로 변환한 로컬 파일은 2026-01-02~2026-10-08의 187일치이며 GitHub에는 올리지 않습니다. 원본이 갱신되면 아래 명령으로 다시 변환하고 대시보드를 재시작하세요. 변환에 `openpyxl`이 필요합니다.

```powershell
python .\import_cash_yields.py '.\기획팀\한국채_금리_조회결과.xlsx' '.\data\cash_daily.csv'
```

`risk.dv01_3y_krw_per_bp`, `risk.dv01_10y_krw_per_bp`, `risk.capital_krw`, `risk.annual_target_vol_fraction`(예: 0.10), `risk.max_package_count`도 입력해야 수량이 나옵니다. 미입력 상태에서는 숫자를 임의로 제시하지 않습니다. 데이터 CSV가 없는 다른 PC에서는 위험 수량을 미연결로 표시합니다.

한 패키지의 일별 손익 **대용치**는 `3년 정수계약수 × 3년 DV01 × 3년 현물금리 변화(bp) − 10년 계약수 × 10년 DV01 × 10년 현물금리 변화(bp)`입니다. 최근 60개 변화와 최근 20개 변화의 표본 표준편차 중 큰 값을 위험 추정치로 사용합니다. 일간 목표 위험액은 `자본 × 연간 목표 변동성 / √252`이며, 이를 1패키지 위험 추정치로 나눈 값을 정수로 내림한 뒤 패키지 수·설정된 총/잔여 DV01 한도로 제한합니다. 현재 날짜의 미완료 관측값은 화면 계산에 포함하지 않으며, CSV 또는 설정을 바꾸면 대시보드를 다시 열어야 합니다. 현물금리와 선물가격 간 베이시스·계약월·DV01 시변화·증거금·실제 포지션은 반영되지 않습니다.

시간순 검증은 미리 정한 평가 시작일을 인수로 전달합니다. 시작일 이전 최소 252개, 이후 최소 60개 일별 변화가 있어야 숫자를 냅니다. 각 평가일의 예측에는 그 전날까지의 금리 변화만 사용하며, 결과는 현물 10Y−3Y 금리차의 **일별 변화 위험 예측**입니다. 선물 매매전략의 OOS 수익률 검증은 아닙니다.

```powershell
.\.venv32\Scripts\python.exe .\cash_risk.py .\data\cash_daily.csv --test-start 2025-01-02 --settings .\settings.json
```

평가 시작일은 데이터 기간에 맞춰 결과를 보기 전에 정해야 합니다. 현재 로컬 187일 표본은 기본 요건(평가 전 252일 + 평가 후 60일)에 미달합니다. 2026-07-01 시작 검사는 학습 119일·평가 67일로 `insufficient_history`를 반환합니다. 장기 데이터가 추가되기 전까지 OOS 합격이나 선물전략 검증을 주장하지 않습니다.

수집을 중단하려면 수집 창에서 `Ctrl+C`를 누릅니다.

## 저부하 동작

- Excel RTD polling: 정상 시 1초(100~2000ms 설정 가능), 연결 오류가 연속되면 3→4→5초 간격 재시도
- 로그: 호가나 체결가가 바뀌면 즉시 기록, 변화가 없으면 5초마다 상태 기록
- 디스크 반영: CSV와 SQLite를 1초 단위로 묶어 반영
- 대시보드: 시작할 때 최근 행만 읽고 이후에는 새로 추가된 행만 분석
- 콘솔: 클릭 실행에서는 매 polling 출력하지 않고 오류만 `launcher.log`에 남김

수집 간격을 늘려도 CheckExpert RTD 자체의 끊김이나 공급값 동결을 해결했다고 볼 수는 없습니다. 1초 사이에 잠깐 닿은 가격은 놓칠 수 있으며, 알림은 관측된 값에 대해서만 동작합니다. 0 호가처럼 Excel 연결은 유지됐지만 시세가 유효하지 않은 경우에는 연결 오류 백오프가 아니라 정상 1초 주기로 재확인합니다.

모든 polling 행이 필요한 진단 상황에서는 `--log-all`을 추가할 수 있습니다.

## 다중 시간대 RV 신호

대시보드는 같은 RV level을 두 시간대로 분리해 표시합니다.

- 빠른 RV: 최근 120개 실제 가격변화 이벤트. 대시보드·수집기·로그 분석기 모두 120개가 쌓이기 전에는 z-score 신호를 내지 않음
- 주 RV: KST 기준 최근 완료된 60개 분의 마지막 관측값. 진행 중인 분은 참조 평균에서 제외하며, 60개가 쌓이기 전에는 신호를 내지 않음
- 종합 판단: 두 z-score가 같은 방향으로 진입 임계값을 넘고 조건이 3초간 유지될 때만 `두 시간대 확인`으로 표시. 비용 기준을 충족하지 못하면 진입 보류
- 초기화: KST 날짜 변경·10초 초과 공백·불량 행에서 재준비. 이는 거래소 야간 세션 달력 구현이 아님

창 길이, beta, 진입·청산 임계값은 `settings.json`에서 바꿀 수 있습니다. 기본 beta `2.88`은 검증 완료된 DV01 값이 아니라 기존 연구값입니다.

계약별 DV01을 확인한 뒤 `risk.dv01_3y_krw_per_bp`와 `risk.dv01_10y_krw_per_bp`에 원/bp 단위로 입력하면 대시보드가 10Y 1계약 기준의 정확한 3Y 헤지 수량, 반올림한 정수 패키지, 잔여 DV01을 표시합니다. 이때 RV 분석 beta도 입력한 DV01 비율로 전환됩니다. 값이 없으면 기존 연구 beta를 사용하며 DV01 결과를 표시하지 않습니다.

## 호가잔량 압력·수동 적정가 비교·가상 위험

- 호가잔량 압력: OBI, WOBI, microprice 위치를 결합한 EMA 점수. 체결 기반 주문흐름은 아님
- 수동 적정가 비교: 정적 입력값과 시장 mid 차이. 실제 현선물 이론가 산출·시점 검증은 미구현
- 가상 위험: 입력 DV01으로 정수 패키지를 계산. 한도 미설정/부분 설정은 미판정이고 실제 포지션 위험은 아님

호가잔량 압력의 가중치와 임계값은 초기 연구 설정이며 검증된 매매 규칙이 아닙니다. 현재 workbook에 체결수량과 체결방향 필드가 없으므로 호가 기반 진단까지만 제공합니다.

## RV 해석 기준

대시보드의 기본 RV z-score는 마지막 체결가 변화량이 아니라 호가 mid 기반 상대가격 수준을 표준화합니다. mid 자체는 체결 가능한 가격이 아닙니다.

```text
RV level = 10Y mid - beta × 3Y mid
RV z-score = (현재 RV level - rolling 평균) / rolling 표준편차
```

체결가는 RV level의 기준값이 아니라 시장 거래 확인용으로 함께 저장됩니다. 빠른 창 전체인 120개 가격 변화 이벤트가 쌓이기 전에는 `데이터 축적 중`으로 표시합니다. `±2` 임계값과 beta `2.88`은 KTB 데이터로 검증 완료된 매매 규칙이 아닌 초기 연구용 값입니다.

## 최근 디버깅 기록

2026-10-19 점검에서는 대시보드가 10/16의 저장 기록을 표시했고 수집기는 기존 CSV와 새 행의 열 구성이 달라 종료됐습니다. 현재는 오늘 날짜 파일만 선택하고 기존 기록을 재생하지 않으며, 선택적 RTD 값이 비어도 저장 열 구성이 변하지 않게 수정했습니다. 기존 로그는 삭제하지 않았습니다. **수집기 창과 대시보드 창을 모두 닫고**, Excel의 RTD 값이 실제 갱신되는지 확인한 다음 위 순서로 다시 시작해야 수정 코드가 적용됩니다. 오늘 파일이 없으면 화면은 `오늘 실시간 데이터 대기`와 `신호 차단`을 표시합니다. 원천 RTD 시각이 없는 항목은 수집 시각만으로 공급자 데이터의 당일 갱신을 증명할 수 없습니다.

추가로 Windows CMD에서 깨진 한글 파일명 검사 때문에 실행 배치가 workbook을 못 찾을 수 있어, `실시간_호가_시작.bat`의 검사를 ASCII wildcard인 `*.xlsx`로 바꿨습니다. Excel이 생성하는 `~$*.xlsx` 임시 잠금 파일은 Git 추적 대상에서 제외합니다.
